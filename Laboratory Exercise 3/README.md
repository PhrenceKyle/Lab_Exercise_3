# ICT Service Request Management System

A web-based Service Request Management System developed for the university's ICT Office to track and manage technical support requests efficiently.

## Features

- **User Authentication**: Login and logout functionality with Supabase Auth (signup disabled - users created manually)
- **Dashboard**: Real-time statistics showing total, pending, in-progress, and completed requests
- **CRUD Operations**: Create, read, update, and delete service requests
- **Data Isolation**: Users can only view and manage their own requests
- **Search**: Search requests by requester name or description
- **Filtering**: Filter requests by status (Pending, In Progress, Completed) and priority (Low, Medium, High)
- **Status Management**: Status field hidden for new requests (defaults to Pending), visible only when editing
- **Responsive Design**: Modern UI that works on desktop and mobile devices
- **Data Validation**: Enforces business rules for data integrity

## Technology Stack

- **Frontend**: HTML5, CSS3, JavaScript (ES6+)
- **Backend**: Supabase (PostgreSQL + Authentication)
- **Deployment**: GitHub Pages
- **Database**: PostgreSQL via Supabase

## Setup Instructions

### Prerequisites

- A Supabase account (free tier available at https://supabase.com)
- A GitHub account for deployment
- Basic knowledge of Git commands

### 1. Supabase Setup

1. **Create a Supabase Project**
   - Go to https://supabase.com and sign up/login
   - Click "New Project"
   - Enter project name (e.g., "ict-service-request")
   - Set database password (save this securely)
   - Select a region closest to you
   - Wait for project to be created (2-3 minutes)

2. **Create the Database Table**
   - Go to SQL Editor in your Supabase dashboard
   - Execute the following SQL:

```sql
CREATE TABLE service_requests (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    requester_name TEXT NOT NULL,
    department TEXT NOT NULL,
    category TEXT NOT NULL,
    description TEXT NOT NULL,
    priority TEXT NOT NULL,
    status TEXT DEFAULT 'Pending',
    created_at TIMESTAMPTZ DEFAULT NOW(),
    user_id UUID REFERENCES auth.users(id)
);
```

3. **Enable Row Level Security (RLS)**
   - Execute the following SQL:

```sql
ALTER TABLE service_requests
ENABLE ROW LEVEL SECURITY;

CREATE POLICY "Users can view their own requests"
ON service_requests
FOR SELECT
TO authenticated
USING (auth.uid() = user_id);

CREATE POLICY "Authenticated users can insert requests"
ON service_requests
FOR INSERT
TO authenticated
WITH CHECK (auth.uid() = user_id);

CREATE POLICY "Authenticated users can update requests"
ON service_requests
FOR UPDATE
TO authenticated
USING (auth.uid() = user_id);

CREATE POLICY "Authenticated users can delete requests"
ON service_requests
FOR DELETE
TO authenticated
USING (auth.uid() = user_id);
```

4. **Get Your Supabase Credentials**
   - Go to Project Settings → API
   - Copy the **Project URL** and **anon/public key**
   - ⚠️ **IMPORTANT**: Never use the service_role key in client-side code

5. **Configure Supabase in the Application**
   - Open `js/supabase.js`
   - Replace the placeholder values:

```javascript
const SUPABASE_URL = "YOUR_SUPABASE_PROJECT_URL";
const SUPABASE_KEY = "YOUR_SUPABASE_ANON_KEY";
```

6. **Create Test Users**
   - Go to Authentication → Users
   - Click "Add User"
   - Enter email and password
   - **Enable "Auto Confirm User"** to skip email confirmation
   - Click Save
   - Repeat for each user who needs access
   - Note: Signup is disabled in the application - users must be created manually

### 2. Local Development

1. **Clone or Download the Project**

2. **Open in Browser**

### 3. GitHub Deployment

1. **Create a GitHub Repository**
   - Go to GitHub and create a new repository
   - Name it: `SAD-ServiceRequest-YourLastname`
   - Initialize with README (optional)

2. **Push Your Code**
   ```bash
   git init
   git add .
   git commit -m "Initial project structure"
   git branch -M main
   git remote add origin <your-repository-url>
   git push -u origin main
   ```

3. **Enable GitHub Pages**
   - Go to your repository on GitHub
   - Click Settings → Pages
   - Under "Build and deployment", select:
     - Source: Deploy from a branch
     - Branch: main
     - Folder: /(root)
   - Click Save
   - Wait 1-2 minutes for deployment
   - Your site will be available at: `https://yourusername.github.io/SAD-ServiceRequest-YourLastname/`

4. **Update Base URL (if needed)**
   - If your repository name affects the path, ensure relative paths in HTML files work correctly
   - The current implementation uses relative paths, so it should work automatically

## Usage

### Login

1. Navigate to the deployed URL or open `login.html`
2. Enter your email and password
3. Click "Login"

### Creating a Request

1. Click "New Request" button
2. Fill in the required fields:
   - Requester Name
   - Department
   - Category
   - Description (minimum 10 characters)
   - Priority (Low, Medium, High)
3. Click "Save Request"

### Viewing Requests

- All requests are displayed in the dashboard table
- Dashboard shows summary statistics at the top

### Editing a Request

1. Click the "Edit" button next to a request
2. Modify the desired fields
3. Click "Save Request"

### Deleting a Request

1. Click the "Delete" button next to a request
2. Confirm the deletion in the modal
3. The request will be permanently removed

### Searching

- Use the search box to find requests by:
  - Requester name
  - Description

### Filtering

- Use the status dropdown to filter by:
  - All, Pending, In Progress, Completed
- Use the priority dropdown to filter by:
  - All, Low, Medium, High
- Filters can be combined with search

## Business Rules Implemented

- **BR-01**: Requester name cannot be empty
- **BR-02**: Department must be provided
- **BR-03**: Category must be selected
- **BR-04**: Description must contain sufficient information (minimum 10 characters)
- **BR-05**: Priority must be Low, Medium, or High
- **BR-06**: New requests automatically receive Pending status
- **BR-07**: Users must log in before managing requests
- **BR-08**: A confirmation must appear before deleting a record
- **BR-09**: Date requested is automatically recorded
- **BR-10**: Unauthorized database modification is prevented via RLS policies

## Security Considerations

- ⚠️ **NEVER** commit the service_role key to GitHub
- Only use the anon/public key for client-side applications
- Row Level Security (RLS) is enabled to protect data
- Users can only view and modify requests they created (data isolation)
- Signup is disabled - users must be created manually by admin

## Troubleshooting

### Common Issues

**Issue**: Cannot connect to Supabase
- **Solution**: Verify your SUPABASE_URL and SUPABASE_KEY are correct in `js/supabase.js`

**Issue**: Login fails
- **Solution**: Ensure you have created a user in Supabase Authentication → Users

**Issue**: Cannot create/update/delete requests
- **Solution**: Verify RLS policies are correctly set up in Supabase SQL Editor

**Issue**: GitHub Pages not loading
- **Solution**: Check GitHub Pages settings and ensure the branch is correctly selected
